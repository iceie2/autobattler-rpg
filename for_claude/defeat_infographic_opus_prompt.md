# Opus prompt: Auto Heroes defeat infographic

Implement a polished, useful defeat infographic for Auto Heroes, our Godot 4.5 autobattler roguelike. Work in this repository. Read root AGENTS.md and autobattler-rpg/CONVENTIONS.md first. There is no version-control safety net: inspect before editing and back up every changed production file. Use existing subscription access only; do not configure or call any paid AI API. This task is the defeat screen, not the upcoming tutorial or map generation.

The current screen reports crystals, rounds, total damage, enemies defeated, and a sentence such as “Shauna dealt 86% of your damage.” Players need to understand the final fight: who stayed alive, who absorbed pressure, what healing accomplished, and how much of the enemy team remained. Build an attractive fantasy battle report that explains this through actual combat data. Keep run totals visibly separate from final-battle statistics.

Inspect these starting points and follow their actual call chains:
- scripts/ui/game_over_screen.gd: GameOverScreen.show_defeat and show_victory; currently a 560×540 panel.
- scripts/core/main_game.gd: defeat presentation, _build_after_action_verdict, run totals, run history and save flow.
- scripts/combat/auto_battle_manager.gd: battle_elapsed (simulation seconds), _after_action snapshots, after_action_rows(), combat lifecycle and death/revive signals.
- scripts/units/unit_base.gd and the real damage/heal/shield application paths: identify authoritative counters and effective-stat accessors before adding telemetry.
- scripts/ui/ui_theme.gd and existing hero portraits/icons/menu chrome: preserve the established fantasy style and both dark/light themes.
- scripts/core/telemetry.gd, telemetry_report.gd and run_history.gd: reuse suitable existing data rather than creating competing counters.

Build this experience:
1. A strong “Defeated” header, biome/encounter/difficulty, final fight duration, and earned crystals. A compact strip presents labeled run totals. Say “Rounds cleared” if counting completed fights/stages; do not count the losing round as survived.
2. A central battle timeline in simulation seconds. Show hero deaths and revivals, plus selected major ability/healing moments where reliable telemetry exists. Use portraits or existing icons and hover details, not a wall of overlapping text. Several events at the same timestamp must remain readable. Handle a long battle with an appropriate scale. Record in simulation time so 0.25×/4× and pause do not distort it.
3. One hero row/card with portrait, name, level, damage dealt, damage taken, effective healing delivered, shields absorbed (where supported), and time alive. Use labeled compact bars with meaningful scales and tooltips. Never let a shared damage ranking imply a support hero was useless. Clarify units, denominators, and whether self-healing is included; separate it if useful. Revival creates multiple alive intervals, not a misleading single first-death lifetime. Distinguish actual HP damage from shield absorption; exclude overheal, overkill and unused shields from effective contributions, or explicitly label raw attempted values if that is what existing counters measure.
4. An enemy survivor panel with portraits/names and remaining/current maximum HP, plus an aggregate HP bar. Explain temporary max-HP changes using the combat-effective accessor. Capture before teardown so dead/freed units do not disappear from the report. Boss phases, summoned units, revived allies, ties, and a zero-damage fight must work.
5. One concise factual takeaway derived from the recorded final fight, such as “Your frontliners fell at 12s; Shauna survived another 8s,” only when verified by timestamps. Avoid unsupported causal diagnoses or automatic strategy prescriptions. Damage share can be a secondary observation. If data is unavailable, hide the affected detail or label it unavailable; never invent numbers.
6. Keep an obvious Return to Main Menu button and preserve crystal payout, victory presentation, existing run history, and save behavior. Fit common window sizes and UI scale settings with scrolling only where necessary. Make details inspectable by mouse; readable labels and icons must not rely on color alone.

Aim for an infographic with hierarchy: a small outcome/reward header, a readable timeline, contribution rows, then enemy survivors and one takeaway. Use warm gold framing, restrained crimson outcome accents, the existing fonts and assets, ample spacing, and subtle reveal animation. Avoid a generic dashboard or pie chart. Prioritize useful information over ornament. Do not create new art through an external generation service.

Use a bounded, immutable final-battle report assembled from authoritative combat events/counters. Preserve hero identity across death/revive and snapshot before resets or queue_free. Record only necessary data; do not add an unbounded log or heavy per-frame allocations. Do not reconstruct the fight from human-readable log text. Audit current counters before trusting them: names like combat_healing_done do not prove every healing source or shielded hit is counted correctly. If instrumentation is missing, implement it at the shared application point, covering basic attacks, abilities, DoTs, reflection, environmental damage, self-heal, team heal, shields, and summons as applicable. Explain attribution policy for sources with no hero owner.

Follow AGENTS.md's truthful-stat contract: all current values must agree with combat through the shared effective-stat calculation. Do not change balance, introduce hidden reductions, or duplicate modifier math in the UI. Keep base/permanent values labeled if shown.

Complete implementation, not just a mockup. Run the required parse/import and boot checks plus focused tests proving final-battle/run-total separation, shielded hits, healing/overheal, early deaths, revival intervals, simulation-time behavior and next-battle reset. Use an isolated disposable APPDATA profile; never overwrite the player's real save or the active playtest profile. Render or capture the final screen with representative solo, four-hero and crowded reports in dark/light themes and a smaller window; inspect and fix clipping/overlap. Synthetic fixtures are fine for layout verification but must never appear as real player results. Deliver a concise explanation of changed files, validation, and any honest instrumentation limitations.
